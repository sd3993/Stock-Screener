How to reach each source, and what has already been found about each, so no session re-researches it; no policy. Which sources count and how filings are stored: `process/data_rules.md`. Investing rules: `process/investing_rules.md`. What each phase does: `process/future/README.md`. Run everything from the project root (PowerShell).

## Settled findings (don't re-research; re-check only when something breaks)
- **screener tools** (the removed MCP's, now called through the library by `scr_tool.py`):
  - `screen_stocks` takes `limit` up to 200, and its sort is server-side.
  - A field named in a query drops the rows where it is empty; column-set fields come back as null.
  - Free accounts keep 15 columns.
  - The per-company tools cut to 8 quarters and 50 announcements; the public page and NSE feeds (`scr_company.py`) don't.
  - Company pages are public; only screens need login.
- **screener has no pledge history** (only the current pledge, as a sentence in its cons, when significant). Pledge history is read from NSE's filed SHP XBRLs.
- **BSE's API is bot-protected:** scripts and curl get 403, and working around it (browser headers, cookies or fingerprints faked) isn't allowed. BSE's API is browser-pane only; its PDFs download with plain curl. NSE goes first for NSE-listed companies.
- **Browser pane can't reach local addresses:** a page's request to 127.0.0.1 gets `ERR_BLOCKED_BY_CLIENT`, and bseindia.com's CSP blocks `eval`, so a snippet can't be loaded from a local server. Data leaves the pane only through a tool result: a result over MAX_MCP_OUTPUT_TOKENS (3,000 tokens, `.claude/settings.local.json`, set at the user's request on 3 Nov 2026) is saved to a tool-results file and shown as a short notice (pad small results so they're saved too).
- **BSE announcements API** (`AnnSubCategoryGetData`) sends 50 rows a page and no page count: page until a page adds no new `NEWSID`.
- **NSE:**
  - Feeds work from scripts through the screener-mcp library's session.
  - XBRL files need that session; plain curl gets nothing.
  - Archive PDFs download with curl from `archives.nseindia.com` (not `nsearchives`).

  Nothing it uniquely offers is needed now.
- **Throughput:** `mb_history.py` manages about 9-13 companies a minute, and screener rate-limits the browser while it runs (login pages show "Too many requests"). `--workers 2` was tested on 3 Nov 2026: about 11 a minute against 9, but 207 cooldowns from 429 errors in 7 minutes, against 124 for 1 worker over the same time: screener's limit is the bottleneck either way, so it stays at 1 worker. Spacing requests further apart keeps the same ~10 a minute with fewer waits: 1.0 s drew 24 cooldowns instead of 124, and 1.2 s none (`SCREENER_MIN_INTERVAL=1.2`, the default in `mb_history.py`, which also widens it 0.05 s per cooldown, and in `scr_company.py`; the library's is 0.25 s). Use it for other bulk screener scripts too. Being logged in doesn't raise the limit: starting at 0.25 s and widening 0.05 s per cooldown, 450 chart requests settled at 1.20 s both logged in and public, with 19 cooldowns each (3 Nov 2026). So scripts stay public and use `--login` only for what needs it (screens).

## Scripts (`tools/scripts/`)
Run as `python tools/scripts/<name>.py`. The run folder comes from `config.py` (`RUN`, or the `RUN` environment variable, else the newest `runs/FY*`).
- **screener.in:** `scr_company.py SYM [--only …]` (one company's screener data, no login and no model tokens; run as `uvx --from screener-mcp==0.5.0 python tools/scripts/scr_company.py SYM`; for a batch, pass several symbols or `--syms-file`, with `--skip-saved` to resume, which saves about 3 s of start-up per company; a background fetch survives a Claude restart, so before resuming one check that no `scr_company.py` python process is still running, or two copies double the request rate), `scr_tool.py <tool> '<args JSON>' <out> [--login]` (calls any tool the screener MCP had, by the same name and arguments, through the library and saves the answer to a file; screens need `--login`; replaces the MCP, removed 3 Nov 2026), `scr_save.py` (only for old MCP answers saved in transcripts), `scr_docs.py SYM` (P6: downloads the results filings, annual reports and transcripts listed in the company's saved screener answers, recorded in `index.json`).
- **Tapetide (not used):** `tt.py`, `tt_docs.py` (its download helpers serve `scr_docs.py`); see `tools/tapetide.md`.
- **Multibagger study (`process/historical/`):** `mb_universe.py` (universe pages → `runs/historical/<date>/universe.csv`), `mb_history.py SYM… | --csv FILE` (long price, P/E, EPS, market-cap-to-sales and sales history from screener's public chart API, back to about 2005; run through uvx like `scr_company.py`), `mb_outcomes.py` (price and market-cap multiples per window from those histories → `runs/historical/<date>/outcomes.csv`), `mb_features.py` (S4 point-in-time features → `features.csv`; usage in `s4_backtest.md`).
- **Phases:** `build_universe.py` (P2 → `universe.csv`), `triage.py` (P3 → `triage.csv`, `gate_batches.json`), `gate_merge.py` (P4R → `gate/decisions.csv`), `facts_check.py SYM` (P6: `facts.json` vs the cached screener and Tapetide figures), `check_pending.py` (after P8: `PENDING: n`).
- **BSE:** `bse_fetch.py job|save` with `bse_fetch.js` (pledge, shareholding, results, corporate actions and announcements for companies NSE doesn't cover, through the browser pane; steps in the script's header). `bse_shp.py` (old shareholding patterns by plain curl, below). `bse_codes.py` (BSE scrip code per NSE symbol: EQUITY_L x the last 5 BSE price files on ISIN, then scr ISIN and an old-price-file name match for delisted ones, marked `name-match` for review, never a guess; writes `data/market/bse_codes.csv`, which `bse_shp.py` falls back to; 4 Nov 2026: 2,490 ISIN matches, 30 name-matches, NSE-only/SME symbols stay unmatched).
- **Documents:** `pdf_text.py <pdf> 1 9999 <out.txt>` (PDF → text with page markers). BSE/NSE fallback only: `bse_pdf.py`, `save_b64_pdf.py`, `save_js_file.py`, `save_last_js.py`.

## screener.in (main source; the screener library through scripts)
The screener MCP was removed on 3 Nov 2026. Company data: `scr_company.py`; any single tool call (screens, peers, …): `scr_tool.py` (both in "Scripts" above).
- **Account:** scripts run with `--login` log in with `SCREENER_USERNAME` and `SCREENER_PASSWORD` from the user-level Claude env config; never read, print or copy them.
  - The account's column set (screener.in → Edit columns, `/user/columns/`) decides which fields every screen row carries; fields named in a query are added on top.
  - The user allowed changing it for this project (3 Nov 2026). Free accounts keep at most 15 columns (screener silently drops the rest on save). It holds exactly the fields in `process/future/screens.json` → `columns`; change both together.
  - To change it, use the browser pane, where the account is logged in, at `/user/columns/`: filter, tick or untick, then Save columns. The list's remove buttons re-render after each click, so re-read the page between clicks.
  - After changing it, check one screen row has every listed field.
- **Public mode, for scripts (no login, no model tokens):** `scr_company.py` and `mb_history.py` import the screener-mcp library through `uvx --from screener-mcp==0.5.0 python …`. The library logs in by itself when `SCREENER_USERNAME` and `SCREENER_PASSWORD` are in the environment (the user sets them in the user-level Claude env config; never read or print them), so these scripts drop them and stay public unless run with `--login`, keeping bulk fetches off the account. Login is for screens (P2, `scr_tool.py screen_stocks … --login`), which public mode can't run.
  - It reads screener's public company pages (all 12 years and 13 quarters, 12 quarters of shareholding, and the credit-rating letters; the per-company tools cut to 8), NSE's feeds (announcements, every row, where `get_company_announcements` caps at 50; insider trades; promoter pledge, latest only; SAST Reg 29; corporate actions; the shareholding-pattern list, about 26 quarters), and the public chart API.
  - NSE feeds query both `index=equities` and `index=sme`, since a company that moved boards has rows under both. The shareholding-pattern XBRLs (`xbrl` link in each quarter's row) are fetched through the library's NSE session; plain curl gets nothing. The promoter-group context `ShareholdingOfPromoterAndPromoterGroup_ContextI` holds the promoter shares and the pledged % of them (`EncumberedShareUnderPledgedAsPercentageOfTotalNumberOfShares`, a fraction); `ShareholdingPattern_ContextI` holds total shares. In NSE's pledge feed, `percPromoterShares` is the promoter pledge (% of promoter shares); `percSharesPledged` counts every holder.
  - The chart API (`/api/company/<id>/chart/?q=…&days=10000`) gives price and volume, P/E with TTM EPS, and market cap to sales with TTM sales back to about 2005, including merged and delisted companies. `&consolidated=true` gives the consolidated series; for standalone, leave the parameter out entirely, since any value (even empty or `false`) returns consolidated, which is all empty for a company without subsidiaries. The answer lists every date with null values where there's no data, so check for values, not for a non-empty list. With `days=10000` the points are weekly: prices are adjusted for splits and bonuses, each volume point is that week's total (TATACHEM, checked against `days=30` daily points, 3 Nov 2026), and market cap to sales has one decimal, so it is coarse for low ratios.
- **Paging:** cover a query of T rows (T ≥ 200) with full 200-row pages only: `sort_by` "Market Capitalization", order desc, pages 1..floor(T/200), then one asc page 1 for the remainder (overlap is fine).
- **Keeping answers out of context:**
  - `scr_tool.py` writes every answer to its `<out>` file (the cache envelope below) and prints only the page and totals for screens, or "saved"; it exits non-zero on an error answer, with the reason in the file.
  - Run it from the Bash tool: PowerShell splits the JSON argument at its inner quotes.
  - Never read a saved file whole into context; scripts read it.
- **`screen_stocks`** (`scr_tool.py screen_stocks '<args>' <out> --login`):
  - `limit` up to 200 rows. Page N makes the server re-fetch pages 1..N from screener (slow; rate limits), so split a big query into market-cap bands of at most 200 rows rather than paging deep.
  - Always set `min_market_cap` 0 (it otherwise adds a ₹100 cr floor) and `exclude_flagged` false (it otherwise drops odd rows).
  - Rows: `symbol`, `name`, `company_id`, `fundamentals` {field: value}. AND/OR/parentheses run natively; field names are screener's exact ones ("Price to Earning", "Historical PE 5Years").
  - A field in the column set comes back on every row, empty or not. A field used in a condition (`X > -9999999`) drops the companies where it is empty, so whole-market fields belong in the column set, not in the query.
- **Per company** (`scr_tool.py <tool> '<args>' <out>`, no login; `scr_company.py` covers the usual items in full):
  - `get_financials`: `statement` profit_loss / balance_sheet / cash_flow / ratios, `financial_type` consolidated / standalone, `years` ≤12, but only the years on screener's page (KRISHNADEF: 4).
  - `get_quarterly_results`: last 8 quarters.
  - `get_shareholding_pattern`: 8 quarters. Pledge is only a flag; the current % is the screen field "Pledged percentage", and the history is `scr/shp_history.json`.
  - `get_insider_trading`: NSE PIT, `days`.
  - `get_company_announcements`: NSE; `category` results / board_meeting / insider_trading / agm / acquisition / fund_raise / credit_rating / …; `days` ≤3650; at most 50 rows per answer, so use categories and windows.
  - `get_document_list`: annual reports back to about 2013, with BSE links; transcripts, some of them on the company website. Some NSE annual-report links download a zip holding the PDF; unzip it before reading.
  - `get_bulk_deals` (last 90 days), `get_company_overview`, `get_peer_comparison`.
- **Cache:** `data/companies/<SYM>/scr/<name>.json`, each `{fetched_at (IST), via, tool, args, warnings, partial, data}`. Names: `profit_loss`, `balance_sheet`, `cash_flow`, `ratios` (and `_standalone` versions), `quarterly`, `shareholding`, `insider`, `announcements`, `documents`, `overview`, `peers`, `credit_ratings`, `pledge_nse`, `sast`, `corporate_actions`, `shareholding_nse`, `history` (multibagger study).
- **Quirks:**
  - Figures are rounded to whole crore.
  - "Public" includes the shareholders Tapetide lists as "Others".
  - Results announcements include newspaper copies: take the "Outcome of Board Meeting" / "Financial Result Updates" filing.
  - A call can fail mid-run (429, dropped connection): the script exits non-zero with the reason; wait and re-run before calling screener unavailable.

## BSE/NSE directly (for what the scripts above don't cover; `process/data_rules.md`)
The screener-mcp library's NSE client (used by `scr_company.py`) sends browser-like headers and loads NSE's homepage for cookies; NSE's terms of use ban automated collection. The user chose to keep using the libraries as they are (4 Nov 2026); don't add header spoofing of our own. No exchange offers a free API; licensed feeds cost lakhs a year (NSE corporate data, BSE data products).
- **BSE PDFs:** `www.bseindia.com/xml-data/corpfiling/AttachHis/<id>.pdf` (same-day filings often under `AttachLive`) with `curl.exe` and its default identity; `AnnPdfOpen.aspx?Pname=<id>.pdf` is the same file. `bse_pdf.py SYM "regex" files...` downloads and extracts. Some transcript links return an HTML page from both paths: use the NSE copy. Large companies sometimes file only a cover letter linking to a website transcript: read the linked file and say so.
- **BSE APIs** (bot-protected, so scripts can't call them): `bse_fetch.py` and `bse_fetch.js` cover the usual items for a batch of about 20 companies, saved to `data/companies/<SYM>/bse/`. For anything else, call api.bseindia.com with fetch() from a www.bseindia.com tab (CORS allowed): `Integratedfinancedata/w?scripcode=` (iXBRL filings since the Mar-2025 quarter), `ConsolidatePledge/w`, `TabResults_SHP/w` (last 3 quarters), `shpSecSummery_New/w?qtrid=<n>.00&scripcode=` (one quarter's pattern; Sep 2026 = 131), `CorporateAction/w`, `ListofScripData/w` (all scrips: `SCRIP_CD`, `scrip_id` = NSE-style symbol), announcements `AnnSubCategoryGetData/w?pageno=&strCat=-1&strPrevDate=YYYYMMDD&strScrip=<code>&strSearch=P&strToDate=&strType=C&subcategory=-1` (12-month window).
- **Old data (checked 4 Nov 2026):** shareholding pattern of any quarter from Mar 2001 (qtrid = 29 + quarters since Mar 2001; Mar 2008 = 57) downloads with plain curl as HTML from `www.bseindia.com/corporates/ShareholdingPattern.aspx?scripcd=<code>&flag_qtr=1&qtrid=<n>.00&Flag=New` (omit `Flag=New` before Jun 2006): promoter shares and %, institutions, pledge from 2009, delisted companies too. `bse_shp.py` fetches and parses them (`--rows FILE` of sym and as_of/start, default the study run's `sample_candidates.csv`; `--want SYM[:CODE]=YYYY-MM..YYYY-MM`; `--plan`; `--reparse`): raw pages and `history.json` in `data/companies/<SYM>/bse/shp/`, log in the run folder; `mb_features.py` reads it. About 1.95 s a request at the default 1.5 s gap. Settled (4 Nov 2026): the page has data through Jun 2022 at most (some companies stop at Dec 2021), blank after and before listing; from Dec 2015 it shows the new-format filing mapped onto the old table (FPIs as "Qualified Foreign Investor", employee-trust shares left out of the total, so promoter % can differ from NSE's by up to ~0.03); its pledge column is % of the category's own shares; promoter % matched NSE's for Sep 2021 - Jun 2022 (Grindwell, Suzlon exactly; Infosys within 0.03). Browser-only: `AnnualReport_New/w?scripcode=` (every annual report from ~1997 with PDF links; the PDFs, `HIS_ANN_RPT/HISTANNR/<yr>/<BSE name of the time>-<code>-MARCH-<yr>.PDF` or `bseplus/AnnualReport/<code>/<code>03<yy>.pdf` from 2010, curl fine and have a text layer), `SHPQNewFormat/w?scripcode=` (quarter list), `Corp_detailedResult_Transpose_ng/w?Scrip_cd=&Qtr=<qtrid>.00` (structured quarterly results from the Sep-2007 quarter: sales, expenses, other income, interest, depreciation, PBT, tax, PAT, equity, EPS; banks in their own format). NSE's SHP list starts Sep 2021 whatever the dates; its annual-report list from ~2010. Screener's Excel export has 10 years (fewer than the page's 12) and its yearly shareholding tab starts Mar 2017.
- **NSE PDFs:** curl to nsearchives.nseindia.com hangs; the same paths download from `https://archives.nseindia.com/corporate/...` (`curl.exe -s -m 60 -o <file> <url>`). Fallback: fetch as base64 inside an nsearchives tab and decode with `save_b64_pdf.py`.
- **NSE APIs** (scripts reach them through the screener-mcp library's NSE session, as `scr_company.py` does; otherwise from a www.nseindia.com tab): `/api/integrated-filing-results` (also `index=sme`), `/api/corporate-share-holdings-master`, `/api/corporates-pit?index=equities|sme&symbol=&from_date=&to_date=` (insider trades, pledges), `/api/corporate-announcements?index=equities&symbol=&from_date=&to_date=`. `corporate-announcements` silently drops rows over wide windows: query one month at a time.
- **Exchange libraries (reviewed 4 Nov 2026, not adopted):** `nsepython` 2.101 (aeron7, GPL-3, single file `rahu.py`; needs curl_cffi, pandas, scipy) reaches nseindia.com only by impersonating Chrome's TLS fingerprint (curl_cffi) to get past Akamai Bot Manager, plus an optional Playwright helper that passes Akamai's JS challenge; `bse` 3.3.4 (BennyThadikaran/BseIndiaApi, GPL-3; needs requests, mthrottle; throttles itself to 8 requests/s) reaches api.bseindia.com, which answers plain curl with Akamai "Access Denied", by sending a Chrome User-Agent, Origin and Referer. Both are bot-detection workarounds, so Claude doesn't run them; no eval, shell-out or telemetry found in either. `bse` has no annual-report, shareholding or detailed-results function anyway (announcements, corporate actions, result calendar, `TabResults_PAR` snapshot of 3 periods, quotes, bhavcopy, scrip lookup). Other free libraries (jugaad-data, nselib, nsetools, bsedata) rely on the same browser imitation. BSE's legacy pages (`corporates/results?...`, `HistoricalAnnualreport?...`) now return only the Angular shell that calls the API, so old structured results and old annual-report lists stay browser-pane only.
- **NSE official MCP servers (no account, plain requests work, checked 4 Nov 2026):** `https://mcp.nseindia.in/bhavcopy/cm/mcp` (21 tools: `get_stock_history` daily OHLCV ≤3 months a call, `get_ltp_by_date`, `get_corporate_actions` with `fromDate`/`toDate` as YYYY-MM-DD, index valuation/history, symbol search) and `.../cmmkt/mcp` (live quotes, gainers/losers). JSON-RPC over HTTP: `initialize` returns an `Mcp-Session-Id`, but the nodes behind the load balancer don't share sessions, so a call 404s about half the time: retry the same call up to 5 times, ~1.6 s apart. Prices only from about Nov 2021 (INFY 2016 and 2008 come back null; GRINDWELL 2022-05-27 close 1743.30 vs screener's weekly 1743.05), some NSE symbols missing (HAWKINCOOK not found), corporate actions from 2007 (same rows as `scr/corporate_actions`). Adds little beyond what we have.
- **BSE code for an NSE symbol (plain curl, checked 4 Nov 2026):** join NSE's `https://archives.nseindia.com/content/equities/EQUITY_L.csv` (SYMBOL, ISIN) with the day's BSE bhavcopy `https://www.bseindia.com/download/BhavCopy/Equity/BhavCopy_BSE_CM_0_0_0_<YYYYMMDD>_F_0000.CSV` (`FinInstrmId` = scrip code, `ISIN`, `TckrSymb`) on ISIN: 2,449 of 2,627 NSE symbols matched (COLPAL 500830, CRISIL 500092, EXIDEIND 500086, COROMANDEL 506395, all correct). Delisted companies: old bhavcopies `.../BhavCopy/Equity/EQ<DDMMYY>_CSV.ZIP` (e.g. 300610) also download by curl; they carry code and name (no ISIN in that old format).
- **Promoter sales:** when the insider (PIT) feed and the SAST Reg 29(2) disclosure disagree on size, read the Reg 29(2) per-person annexure first (it covers everyone acting in concert). Settle promoter-group membership from Reg 31(4) declarations and the shareholding pattern's promoter list. A fall in promoter share count with unchanged total shares means a sale, transfer out or reclassification.
- **Scanned PDFs** give no text (no OCR here); render pages as images and read them, and say so. Extract page images with pypdf's `page.images` (Pillow); image-mask pages that won't render are read from the OCR text layer and checked by arithmetic. Mixed-raster SAST PDFs: wrap each layer's raw stream (pypdf) in a TIFF header, convert to PNG (.NET System.Drawing) and read the image.
- **Browser pane:** WebFetch can't open nseindia.com or bseindia.com; don't spoof a browser. Each helper opens one tab of its own, passes its tabId on every call and closes it when done. `javascript_tool` times out at 45 s: start long work un-awaited and poll; save large results with `save_js_file.py`. Never wait on a script or download more than about a minute: reload and retry up to three times, then report the company as unfinished.
- **XBRL quirks:** owners'-share PAT tags are sometimes 0 or wrong for a single quarter (cross-check the results PDF); some filers tag income tax paid under investing.

## Zerodha Kite (Kite CLI)
Official CLI from zerodha/kite-cli (MIT; never the unofficial `kitecli` PyPI package or jogendra/kite-cli). Installed 3 Nov 2026; replaces the Kite MCP (removed 3 Nov 2026). Show the Kite warning in `CLAUDE.md` whenever asking the user to log in.
- **Install:** v0.2.1 (newest tag then) from the GitHub release zip `kite-0.2.1-x86_64-pc-windows-msvc.zip`, SHA-256 matched the release's `checksums.txt`; `kite.exe` is in `C:\Users\sd391\AppData\Local\Programs\kite\` (on the user PATH only; open a new terminal). Update by repeating this with the new release.
- **Login (the user types it in their own terminal; Claude never runs it, asks for or types the user ID, password or 2FA):** `kite auth login` (optionally `kite auth login AB1234`). It prompts in the terminal for user ID, password (masked), a 2FA method and the TOTP/OTP code; needs an interactive TTY and refuses `--json` or piped input. Then `kite doctor` checks the session (one read-only call, `GET /user/margins`). Logout: `kite auth logout` (only if the user asks).
- **Session (docs; login and storage confirmed 3 Nov 2026, daily expiry still to confirm):** stored in `%APPDATA%\kite\config.json` (`kite config path` prints it) as `user_id` and `access_token`; no password or 2FA is stored. Never read or print that file, `KITE_ACCESS_TOKEN` or `KITE_API_KEY`. The token expires daily around 06:00 IST (sooner if another login or logout invalidates it) and is not renewed, so the user logs in again each day. After login, commands run non-interactively and share the session.
- **Read-only commands (always with `--json`):** `kite --json user profile`, `kite --json user margins [--segment equity]`, `kite --json portfolio holdings`, `kite --json portfolio positions` (`net` and `day` arrays), `kite --json orders list`, `kite --json orders trades`, `kite --json mf holdings`, `kite --json market ltp NSE:INFY`, `kite --json market resolve NSE:INFY`, `kite --json doctor`. On success the JSON is the bare result (holdings: a list of objects); errors come as `{"ok": false, "error": {...}}` on stdout; exit 0 ok, 1 runtime/API error, 2 usage error. Holdings JSON: `tradingsymbol`, `quantity`, `t1_quantity`, `collateral_quantity`, `mtf.quantity`, `last_price` (combine the quantities for the full position).
- **Holdings script:** `python tools/scripts/kite_holdings.py` (P1 and before P9) writes the same holdings to two copies: `data/kite/holdings.csv` (latest: sym, exchange, isin, name, qty, avg_cost, last_price, google_code, screener_url, fetched_at) plus `data/kite/holdings_<date_time>.json` (the CLI's answer), outside the runs and git-ignored; and the sheet's Holdings tab through gws (RAW), data columns only: Z Ticker, B Name, C Qty, D Avg cost, N Google code, O Screener URL, P Stored price, Q Kite stale (FALSE), V ISIN (header "[h] ISIN"), and the fetch time (IST) in the Notes header cell, M1: "Notes · Kite fetched YYYY-MM-DD HH:MM" (column M is 260 px wide so it isn't clipped; if Kite is unavailable M1 keeps the last real fetch; `--latest` parses the time from M1, falling back to the old U1 if M1 has none). It never writes F Status or the Notes cells M2 down (P9's) and never deletes rows. Rows match by ISIN (column V), else by ticker; a new holding takes the first row with Z empty; a sheet holding no longer in Kite gets Qty 0 (P9 removes the row). It reads the tab back and checks Qty, Avg cost and the stamp.
  - Values: qty = `quantity` plus any T+1, collateral and MTF quantities (none held when written, 3 Nov 2026, so it prints CHECK when one appears, to confirm against Kite web once). ## The sheet (built 24 Oct 2026; `1yBV2fZiIR9xgZ3r-5feDKF_urqXspkPLLG9wPDoPtDU`)
Final outcomes only, light colours only, related columns merged to limit horizontal scrolling.
- **Tabs and sheetIds:** Short term 101, Medium term 102, Long term 103, Allocation 7, Holdings 104, Pending results 105 (renamed each quarter; its name is in Data!BA1), Data 106, Data Flags 10. Formulas are pre-filled (Data rows 2-300, bucket tabs 2-200, Holdings/Allocation 2-100). Which columns each phase writes: `process/future/p8_listing.md` (Data, Data Flags, Pending) and `process/future/p9_allocation.md` (Holdings, Allocation); every other column is a formula and is never written.
- **Data:** one row per analysed company. Formula columns AD:AZ and BD: live price chain, P/E now, forward P/E, PEG, multiples and CAGR per bucket (base multiple = horizon-end base EPS × exit P/E + dividends, ÷ live price; CAGR over 2/5/7 years), bear multiples, short-term target price and % to target, re-rating share, pending flag, data-flag flag, held flag. BA1 holds the pending tab's name.
- **Bucket tabs:** live formula views of Data (hidden column Z is the sorted ticker list), sorted by expected CAGR, descending. A company is listed when P7 made it eligible for that bucket (nested: long ⇒ medium ⇒ short) and its non-negotiables aren't Fail; a holding is always listed (its closest bucket if eligible for none). Price moves never remove a row: when the live price breaks a rule (CAGR < 25%, bear < 0.8x, forward P/E ≥ 50 or negative, PEG > 2 or negative), or the company fails a non-negotiable or isn't eligible (holdings), the row's text turns red and "Below rule (live)" lists every reason. Short term also has target price, % to target and a sell-trigger cell; medium and long show exit P/E and re-rating share. Each row links to the company's other bucket tabs.
- **Allocation:** P9's actions with live price, current value and bucket links; P1:S4 shows each bucket's share of target and current value against its range, a multi-bucket position counted equally in each bucket. The range text in Q2:Q4 copies rule 18 of `process/investing_rules.md`; update it whenever that rule changes.
- **Holdings:** P9's status per holding with live price, value, P&L and bucket links.
- **Live price chain:** GOOGLEFINANCE (`NSE:SYM` or `BOM:<code>`); if N/A, screener.in's price via IMPORTXML from the "Screener URL" column (a sheet formula, not a research source); if that fails too, the stored price from the last P8.
- **Colours, one meaning each** (a cell colour overrides the row colour on that cell; red text combines with any fill): row light yellow = results pending; ticker cell light red = data flag (links to the company's first row in Data Flags); price cell light orange = screener price, light grey = stored price; sell-trigger cell light green = short-term target hit; Holdings Qty and Avg-cost cells light blue = Kite didn't refresh; red text = a rule broken (reasons in "Below rule (live)").
