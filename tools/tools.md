# Tools: how to reach each source, the scripts, and the sheet's layout

Method only, no findings and no policy. Which sources count and how filings are stored: `process/data_rules.md`. Investing rules: `process/investing_rules.md`. What each phase does: `process/README.md`. Run everything from the project root (PowerShell).

## Scripts (`tools/scripts/`)
Run as `python tools/scripts/<name>.py`. The run folder comes from `config.py` (`RUN`, or the `RUN` environment variable, else the newest `runs/FY*`).
- **Tapetide:** `tt.py` (REST client: `usage`, `get <route> k=v [--save PATH] [--all-pages]`, `calls [days]`, `log-mcp <route> <sym>`; caching and call log for every other script), `tt_screens.py` (P2), `tt_gate.py --batch N | SYM…` (P4 pre-fetch), `tt_company.py SYM [--refresh]` (P6 fetch and downloads), `tt_docs.py` (shared: filings/documents lists, downloads, `index.json`), `save_last_result.py` (saves an MCP answer to a file when there's no token).
- **Phases:** `build_universe.py` (P2 → `universe.csv`), `triage.py` (P3 → `triage.csv`, `gate_batches.json`), `gate_merge.py` (P4R → `gate/decisions.csv`), `facts_check.py SYM` (P6: `facts.json` vs Tapetide), `check_pending.py` (after P8: `PENDING: n`).
- **Documents:** `pdf_text.py <pdf> 1 9999 <out.txt>` (PDF → text with page markers). BSE/NSE fallback only: `bse_pdf.py`, `save_b64_pdf.py`, `save_js_file.py`, `save_last_js.py`.

## Tapetide (`mcp__af235b6b-af53-412d-8753-14cb1ee41e3c__*` and REST)
- **Two ways in, one quota.** The MCP tools and the REST API (`https://api.tapetide.com/v1`, bearer token from `TAPETIDE_TOKEN`; the user creates the personal token, `tpt_rt_…`, at https://tapetide.com/settings/tokens) share the same counters: one call costs one unit, failed calls are refunded. Free plan: 50 a day. Starter plan: 400 a day and 5,000 a month. `python tools/scripts/tt.py usage` shows the position (free route). Prefer the scripts when a token is set: REST pages are larger and untruncated, and scripts save answers without spending model tokens.
- **Downloads are free:** a parsed document's `links` (`pdf_url`, `markdown_url`, page Markdown) on filings.tapetide.com, and the exchange links (`url`) in the filings list (`www.bseindia.com/stockinfo/AnnPdfOpen.aspx?Pname=…`), download with `curl.exe -s -L` and use no quota.
- **Cache:** `data/companies/<SYM>/api/<name>.json`, each `{fetched_at (IST), via, route, params, data}`. Names: `financials` (all sections, all periods), `shareholding`, `pledge`, `pledge_events`, `insider`, `sast`, `deals`, `filings` (3 years), `documents`, `credit_ratings`, `corporate_actions`, `profile` (with peers), `quote`. Market-wide answers go in `data/market/`.
- **Call log:** `data/calls.csv` (ts_ist, via, route, symbol, params, status, run). Scripts log their own calls; a helper using MCP tools logs each call by saving it with `save_last_result.py` (or `tt.py log-mcp <tool> <SYM>` for one it doesn't save). `python tools/scripts/tt.py calls` prints calls per day.
- **Saving an MCP answer** (no token): right after the call, `python tools/scripts/save_last_result.py --marker <a word in the answer> --out data/companies/<SYM>/api/<name>.json --wrap <tool name> --sym <SYM> --tag <tag from your brief>`; for screen pages `--marker total_pages --out <run>/screens/<ID>_pNN.json --page <n> --tag <tag>`. It refuses a cut-off answer.
- **MCP tools and their REST routes** (REST: `/v1/stocks/{symbol}/…`): `get_financials` (`/financials`; `section` quarterly / profit_loss / balance_sheet / cash_flow / ratios; `periods` up to 40), `get_shareholding` (`/shareholding`, includes the promoter pledge block), `get_promoter_pledge` (`/promoter-pledge`, `/promoter-pledge/events`), `get_stock_deals` (`/insider-trades` with transaction types buy/sell/pledge/pledge_release/pledge_invocation/esop, `/sast-disclosures`, `/bulk-block-deals`), `get_stock_events` type filings (`/filings`, with `category`: financial_results, annual_report, earnings_call, investor_presentation, credit_rating, capital_raise, insider_takeover, management_change, orders_contracts, acquisition, insolvency, compliance, …; REST pages up to 200), `list_company_documents` / `get_document_summary` / `read_document` (`/documents…`), `get_company_profile` (`/v1/stocks/{symbol}?include=peers`), `get_credit_ratings` (`/credit-ratings`), `get_stock_events` corporate_actions (`/corporate-actions`), `get_price_history` (`/prices/daily`, up to 2,000 days a call), `get_batch_quotes` (`/v1/quotes?symbols=`, 20 a call), `screen_stocks` (`/v1/screens/fundamental`), `get_screener_ratios` (`/v1/screens/fundamental/fields`). Point-in-time fundamentals with a chosen basis: `/fundamentals?basis=consolidated|standalone&as_of=`.
- **Screener** (`screen_stocks`): the same query language and ratio names as screener.in ("Price to Earning", "Historical PE 5Years"; exact names, or the query errors). MCP pages over ~30 rows get cut at the 25,000-character tool-result limit: use `limit` 25. Each MCP query returns only two fields beyond the nine default columns, keyed by short names (`5yrs_pe`, `cf_opr_3yrs_rs.cr.`); REST returns every queried ratio by its full name in `ratio_values`. "Historical PE 5Years" is a 5-year median.
- **Quirks:** in `get_shareholding`/`get_promoter_pledge`, `pct_of_promoter_holding` is the promoter pledge; `all_holders_pledged_pct_of_demat_shares` (alias `pct_total_shares_pledged`) counts every holder and is not a promoter figure. A bucket moving more than 5 points in one quarter may be a filing reclassification. Statements don't always label their basis (consolidated/standalone): confirm against the results filing. `available_from` in financials is the declaration date (for look-ahead-free history), but values are the latest restated ones. Parsed text is Tapetide's own conversion and some documents are mislabelled: read decisive figures from the PDF page. The filings list's `concall_audio` rows are often the transcript filing itself. `get_stock_deals` without a type mixes old bulk deals with insider rows: use the REST `insider-trades` and `sast-disclosures` routes (or `type`) for promoter activity.

## BSE/NSE fallback (only for what Tapetide lacks; `process/data_rules.md`)
- **BSE PDFs:** `www.bseindia.com/xml-data/corpfiling/AttachHis/<id>.pdf` (same-day filings often under `AttachLive`) with `curl.exe` and its default identity; `AnnPdfOpen.aspx?Pname=<id>.pdf` is the same file. `bse_pdf.py SYM "regex" files...` downloads and extracts. Some transcript links return an HTML page from both paths: use the NSE copy. Large companies sometimes file only a cover letter linking to a website transcript: read the linked file and say so.
- **BSE APIs** (curl gets 403): in the browser pane, open a tab on www.bseindia.com and call api.bseindia.com from it with fetch() (CORS allowed): `Integratedfinancedata/w?scripcode=` (iXBRL filings since the Mar-2025 quarter), `ConsolidatePledge/w`, `TabResults_SHP/w`, `ListofScripData/w`, announcements `AnnSubCategoryGetData/w?pageno=&strCat=-1&strPrevDate=YYYYMMDD&strScrip=<code>&strSearch=P&strToDate=&strType=C&subcategory=-1` (12-month window).
- **NSE PDFs:** curl to nsearchives.nseindia.com hangs; the same paths download from `https://archives.nseindia.com/corporate/...` (`curl.exe -s -m 60 -o <file> <url>`). Fallback: fetch as base64 inside an nsearchives tab and decode with `save_b64_pdf.py`.
- **NSE APIs** (from a www.nseindia.com tab): `/api/integrated-filing-results` (also `index=sme`), `/api/corporate-share-holdings-master`, `/api/corporates-pit?index=equities|sme&symbol=&from_date=&to_date=` (insider trades, pledges), `/api/corporate-announcements?index=equities&symbol=&from_date=&to_date=`.
- **Promoter sales:** when the insider (PIT) feed and the SAST Reg 29(2) disclosure disagree on size, read the Reg 29(2) per-person annexure first (it covers everyone acting in concert). Settle promoter-group membership from Reg 31(4) declarations and the shareholding pattern's promoter list. A fall in promoter share count with unchanged total shares means a sale, transfer out or reclassification.
- **Scanned PDFs** give no text (no OCR here); render pages as images and read them, and say so. Mixed-raster SAST PDFs: wrap each layer's raw stream (pypdf) in a TIFF header, convert to PNG (.NET System.Drawing) and read the image.
- **Browser pane:** WebFetch can't open nseindia.com or bseindia.com; don't spoof a browser. Each helper opens one tab of its own, passes its tabId on every call and closes it when done. `javascript_tool` times out at 45 s: start long work un-awaited and poll; save large results with `save_js_file.py`. Never wait on a script or download more than about a minute: reload and retry up to three times, then report the company as unfinished.
- **XBRL quirks:** owners'-share PAT tags are sometimes 0 or wrong for a single quarter (cross-check the results PDF); some filers tag income tax paid under investing.

## The sheet (built 24 Oct 2026; `1yBV2fZiIR9xgZ3r-5feDKF_urqXspkPLLG9wPDoPtDU`)
Final outcomes only, light colours only, related columns merged to limit horizontal scrolling.
- **Tabs and sheetIds:** Short term 101, Medium term 102, Long term 103, Allocation 7, Holdings 104, Pending results 105 (renamed each quarter; its name is in Data!BA1), Data 106, Data Flags 10. Formulas are pre-filled (Data rows 2-300, bucket tabs 2-200, Holdings/Allocation 2-100). Which columns each phase writes: `process/p8_listing.md` (Data, Data Flags, Pending) and `process/p9_allocation.md` (Holdings, Allocation); every other column is a formula and is never written.
- **Data:** one row per analysed company. Formula columns AD:AZ and BD: live price chain, P/E now, forward P/E, PEG, multiples and CAGR per bucket (base multiple = horizon-end base EPS × exit P/E + dividends, ÷ live price; CAGR over 2/5/7 years), bear multiples, short-term target price and % to target, re-rating share, pending flag, data-flag flag, held flag. BA1 holds the pending tab's name.
- **Bucket tabs:** live formula views of Data (hidden column Z is the sorted ticker list), sorted by expected CAGR, descending. A company is listed when P7 made it eligible for that bucket (nested: long ⇒ medium ⇒ short) and its non-negotiables aren't Fail; a holding is always listed (its closest bucket if eligible for none). Price moves never remove a row: when the live price breaks a rule (CAGR < 25%, bear < 0.8x, forward P/E ≥ 50 or negative, PEG > 2 or negative), or the company fails a non-negotiable or isn't eligible (holdings), the row's text turns red and "Below rule (live)" lists every reason. Short term also has target price, % to target and a sell-trigger cell; medium and long show exit P/E and re-rating share. Each row links to the company's other bucket tabs.
- **Allocation:** P9's actions with live price, current value and bucket links; P1:S4 shows each bucket's share of target and current value against its range, a multi-bucket position counted equally in each bucket. The range text in Q2:Q4 copies rule 18 of `process/investing_rules.md`; update it whenever that rule changes.
- **Holdings:** P9's status per holding with live price, value, P&L and bucket links.
- **Live price chain:** GOOGLEFINANCE (`NSE:SYM` or `BOM:<code>`); if N/A, screener.in's price via IMPORTXML from the "Screener URL" column (a sheet formula, not a research source); if that fails too, the stored price from the last P8.
- **Colours, one meaning each** (a cell colour overrides the row colour on that cell; red text combines with any fill): row light yellow = results pending; ticker cell light red = data flag (links to the company's first row in Data Flags); price cell light orange = screener price, light grey = stored price; sell-trigger cell light green = short-term target hit; Holdings Qty and Avg-cost cells light blue = Kite didn't refresh; red text = a rule broken (reasons in "Below rule (live)").
