# Data rules (read by every phase that fetches or uses figures: P2-P7)

How to reach each source (routes, scripts, quirks) is in `tools/tools.md`. This file says which sources count and how to treat them.

## Sources
- **Tapetide is the data source.** Figures (quarterly and annual statements, ratios, screens), shareholding, pledge, insider/SAST/bulk/block deals, credit ratings, corporate actions, the list of exchange filings, and parsed copies of transcripts, annual reports and presentations all come from Tapetide. screener.in is not used.
- **Filed documents are ground truth.** A figure that decides an outcome (a reject, a non-negotiable, an EPS path, a data flag) is checked against the filed document itself: the results filing, annual report or shareholding pattern. Get the document through Tapetide: a parsed document's `pdf_url`/`markdown_url`, or the exchange link in Tapetide's filings list (`url`/`source_url`). Both are the exchange's own copy. On a mismatch, rule out definition gaps first (standalone vs consolidated, restatements, bonus/split, one-offs, TTM vs FY, units), then use the filing, record both values as a data flag, and re-check Tapetide's other figures for the company.
- **Basis:** use consolidated figures where the company files them, standalone otherwise, and say which. Tapetide's statements don't label their basis in every route: confirm it against the results filing on a company's first fetch and record it in `index.json`.
- **BSE/NSE directly** only for something specific Tapetide lacks: a filing missing from its list, an unparsed or unreadable document with no working link, an SME company it doesn't cover, a SAST per-person annexure, or a figure that needs the exchange's XBRL. Say what was missing and why in the company's `index.json` (`missing` and `fetched_direct`) and in `process/fetch_learnings.md`. BSE by default; NSE when BSE lacks the document or it's unreadable there. Record which exchange each file came from.
- **Which document:** take every document from the exchange filing, not the company website or a third party; use those only when the exchange has no copy (or the filing itself links to it), say so, and note it in unknowns. Rank by assurance: audited annual figures > limited-reviewed quarterly/half-year figures > unaudited statutory disclosures (shareholding, pledge, SAST/insider) > presentations and call transcripts (guidance and explanations only, never figures that override results).
- **Guidance and news** come only from exchange disclosures, never from news sites, blogs, broker notes, analyst estimates or other websites. Tapetide's own digests (`get_document_summary`, `get_earnings_call_summary`), its news feed, its analyst forecasts and its Tapetide Score are pointers only: every number or claim used is read in the filed document itself.
- **Known Tapetide quirks** (in `tools/tools.md`): the all-holders pledge field is not a promoter figure; a shareholding bucket moving more than 5 points in a quarter may be a reclassification; parsed document text is Tapetide's own conversion, so a decisive figure is read from the PDF page.

## Calls and caching
- Every Tapetide answer is saved in `data/companies/<SYM>/api/` (market-wide ones in `data/market/`) with its fetch date, and every call is logged (`tools/tools.md`). Read the cache before calling; call again only when the data may have changed since (new results, shareholding or filings since the fetch date) or when a doubt needs a fresh copy.
- Downloads from the free document links (`filings.tapetide.com`, exchange PDFs) don't use the call quota.

## Storing company data (`data/companies/<SYM>/`)
- One folder per company holds everything about it, whatever the source: documents in quarter folders, Tapetide answers in `api/`, and `index.json`, `facts.json`, `facts_check.json`, `search_log.json` at the top.
- Documents go in quarter subfolders `<FYyyQn>/` (year first, e.g. `FY27Q1`): a quarter's results, call transcript, presentation and shareholding together; an annual report under that year's Q4 (AR FY26 → `FY26Q4`); ad-hoc announcements by the quarter of their filing date. `index.json`, `facts.json` and `facts_check.json` stay in `data/companies/<SYM>/` itself. Files left loose by earlier sessions are moved into their quarter subfolder.
- **No re-downloads:** `index.json` records the company's latest declared quarter, last fetch date and, for every file, its source (Tapetide doc_id or exchange attachment ID), source URL and SHA-256. List the company's filings first and download only what isn't in the index; if a new file has the same SHA-256 as one already held, record it but keep no second copy. Prefer Tapetide's Markdown (`.md`) for reading and keep the PDF for figures that decide outcomes. A repeat fetch with nothing new downloads nothing. Every phase that downloads records the file in `index.json` (creating it if missing); P6 also indexes any file in the folder that isn't in `index.json` yet.
- **Missing documents** listed in `index.json` are searched for again on every fetch.
- **Superseded documents:** when the company re-files a document (revised results, a corrigendum, a re-filed shareholding pattern or transcript), rename the old file and its text with the suffix `_superseded` before the extension and update its name in `index.json`. No phase reads superseded files.
- **Individual figures** need no marking: `facts.json` keeps one value per figure, the highest-assurance one (audited over limited-reviewed), the latest filed among equals, with its source document and page.
- Never delete downloads; only the user decides that, if space runs out.
