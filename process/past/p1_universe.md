# P1: universe, history and outcomes (scripts, run by the orchestrator)

1. **Universe screens** (`scr_tool.py screen_stocks '<args>' <file> --login`, `limit` 200; each page saved to a file and never read into context; paging as in `process/future/f2_screens.md`). One band per market-cap range, IDs `U00`-`U08`:
   `Market Capitalization > 0 AND Market Capitalization <= 20`, then >20 ≤50, >50 ≤100, >100 ≤200, >200 ≤500, >500 ≤1500, >1500 ≤5000, >5000 ≤20000, >20000.
   Save as `runs/past/<date>/universe/U<band>_<desc|asc>_p<n>.json`. Paging: desc pages 1…floor(total/200), then asc page 1.
2. **Delisted candidates:** `data/market/reference_stocks_delisted.json` (Tapetide's master list, 136 names in Nov 2026). On a re-run, also check NSE's and BSE's delisted/merged lists for names since, and add their screener pages where they exist.
3. `python -I tools/scripts/mb_universe.py` → `universe.csv`. Run it after each band's pages, before the next band. It prints each saved band's count against screener's total: every band must match (a short band means a page is missing; fetch it). The last run gives the full file.
4. **History:** `uvx --from screener-mcp==0.5.0 python tools/scripts/mb_history.py --csv runs/past/<date>/universe.csv` with `run_in_background`, logging to the session scratchpad (`… > <scratchpad>/mb_history.log 2>&1`). About 3 public chart requests a company, no login, no model tokens; about 7 hours for ~5,700 companies. It skips saved companies, so a restart resumes. Never start a second copy (check `Get-CimInstance Win32_Process` for `mb_history.py`). Screener answers 429 when hit too hard: if the log shows 429s, stop it, wait, and resume. Create the half-hourly watchdog. While it runs, check a few saved histories for values, including a standalone-only company (Abbott India) and a small BSE company: the answer lists every date, with nulls where there's no data, so a saved file proves nothing (`tools/tools.md`). After a fix to the script, `--recheck-empty` refetches the saved companies with an empty series (2,102 companies took about 3.5 hours); then re-run step 5.
5. **Outcomes:** `python -I tools/scripts/mb_outcomes.py` → `outcomes.csv`: per company and quarter-end start since Mar 2006, the price and market-cap multiples over 2, 3, 5, 7 and 10 years and the peak inside each window, with what was visible at the start (market cap, P/E and its own 5-year median, TTM EPS and sales and their 1- and 3-year growth, prior 1-year price return). Start values are point in time by `mb_features.py`'s rules (its header: chart EPS and sales steps stamped on a quarter end count from the filing lag; market cap = market cap to sales x the sales on that same chart date); price multiples need no lag. `--out FILE` writes elsewhere (tests).
6. **Industry labels:** for the whole universe, up front, since P8 draws peers from them: `uvx --from screener-mcp==0.5.0 python tools/scripts/scr_company.py --syms-file <list of universe.csv's sym column> --only overview --skip-saved`, in the background and after the history fetch (same source, so never beside it). About 4 hours for 4,560 companies (Nov 2026: 4,522 with a label, 0 failures).
7. Record in `status.md`: universe counts, history saved/failed, labels, outcomes rows; note companies with no history and why (no chart data, merged before 2006, etc.).
