# screener.in (main source; the screener library through scripts)
Company data: `scr_company.py`; any single tool call (screens, peers, …): `scr_tool.py` (both in `/scripts/SCRIPTS.md`).
- **Never skipped:** screener.in is needed for every stock. If it can't be reached, never skip it or do a step partially without it: try to restore it (check the script's error, the login, the rate limit), and if you can't, pause the steps that need it, tell the user and wait.
- **Account:** the login is in the user-level environment configuration as `SCREENER_USERNAME` and `SCREENER_PASSWORD`; scripts use it with `--login`. The account is a throwaway, and its screener.in settings (such as its column set) may be changed to get data efficiently.
  - The account's column set (screener.in → Edit columns, `/user/columns/`) decides which fields every screen row carries; fields named in a query are added on top.
  - Free accounts keep at most 15 columns (screener silently drops the rest on save). It holds exactly the fields in `/workflow/screens.json` → `columns`; change both together.
  - To change it, use the browser, where the account is logged in, at `/user/columns/`: filter, tick or untick, then Save columns. The list's remove buttons re-render after each click, so re-read the page between clicks.
  - After changing it, check one screen row has every listed field.
- **Public mode, for scripts (no login, no model tokens):** `scr_company.py` and `mb_history.py` import the screener-mcp library through `uvx --from screener-mcp==0.5.0 python …`. The library logs in by itself when the login is in the environment, so these scripts drop it and stay public unless run with `--login`, keeping bulk fetches off the account. Login is for screens (S2, `scr_tool.py screen_stocks … --login`), which public mode can't run.
  - It reads screener's public company pages (all 12 years and 13 quarters, 12 quarters of shareholding, and the credit-rating letters; the per-company tools cut to 8), NSE's feeds (announcements, every row, where `get_company_announcements` caps at 50; insider trades; promoter pledge, latest only; SAST Reg 29; corporate actions; the shareholding-pattern list, about 26 quarters), and the public chart API.
  - NSE feeds query both `index=equities` and `index=sme`, since a company that moved boards has rows under both. The shareholding-pattern XBRLs (`xbrl` link in each quarter's row) are fetched through the library's NSE session; plain curl gets nothing. The promoter-group context `ShareholdingOfPromoterAndPromoterGroup_ContextI` holds the promoter shares and the pledged % of them (`EncumberedShareUnderPledgedAsPercentageOfTotalNumberOfShares`, a fraction); `ShareholdingPattern_ContextI` holds total shares. In NSE's pledge feed, `percPromoterShares` is the promoter pledge (% of promoter shares); `percSharesPledged` counts every holder.
  - The chart API (`/api/company/<id>/chart/?q=…&days=10000`) gives price and volume, P/E with TTM EPS, and market cap to sales with TTM sales back to about 2005, including merged and delisted companies. `&consolidated=true` gives the consolidated series; for standalone, leave the parameter out entirely, since any value (even empty or `false`) returns consolidated, which is all empty for a company without subsidiaries. The answer lists every date with null values where there's no data, so check for values, not for a non-empty list. With `days=10000` the points are weekly: prices are adjusted for splits and bonuses, each volume point is that week's total (checked on TATACHEM against `days=30` daily points), and market cap to sales has one decimal, so it is coarse for low ratios.
- **Paging:** cover a query of T rows (T ≥ 200) with full 200-row pages only: `sort_by` "Market Capitalization", order desc, pages 1..floor(T/200), then one asc page 1 for the remainder (overlap is fine).
- **Keeping answers out of context:**
  - `scr_tool.py` writes every answer to its `<out>` file (the cache envelope below) and prints only the page and totals for screens, or "saved"; it exits non-zero on an error answer, with the reason in the file.
  - Run it from a bash shell: PowerShell splits the JSON argument at its inner quotes.
  - Never read a saved file whole into context; scripts read it.
- **`screen_stocks`** (`scr_tool.py screen_stocks '<args>' <out> --login`):
  - `limit` up to 200 rows, and the sort is server-side. Page N makes the server re-fetch pages 1..N from screener (slow; rate limits), so split a big query into market-cap bands of at most 200 rows rather than paging deep.
  - Always set `min_market_cap` 0 (it otherwise adds a ₹100 cr floor) and `exclude_flagged` false (it otherwise drops odd rows).
  - Rows: `symbol`, `name`, `company_id`, `fundamentals` {field: value}. AND/OR/parentheses run natively; field names are screener's exact ones ("Price to Earning", "Historical PE 5Years").
  - A field in the column set comes back on every row, empty or not. A field used in a condition (`X > -9999999`) drops the companies where it is empty, so whole-market fields belong in the column set, not in the query.
- **Per company** (`scr_tool.py <tool> '<args>' <out>`, no login; `scr_company.py` covers the usual items in full):
  - `get_financials`: `statement` profit_loss / balance_sheet / cash_flow / ratios, `financial_type` consolidated / standalone, `years` ≤12, but only the years on screener's page (KRISHNADEF: 4).
  - `get_quarterly_results`: last 8 quarters.
  - `get_shareholding_pattern`: 8 quarters. Pledge is only a flag (a sentence in screener's cons, when significant); the current % is the screen field "Pledged percentage", and the history, which screener lacks, is read from NSE's filed SHP XBRLs into `scr/shp_history.json`.
  - `get_insider_trading`: NSE PIT, `days`.
  - `get_company_announcements`: NSE; `category` results / board_meeting / insider_trading / agm / acquisition / fund_raise / credit_rating / …; `days` ≤3650; at most 50 rows per answer, so use categories and windows.
  - `get_document_list`: annual reports back to about 2013, with BSE links; transcripts, some of them on the company website. Some NSE annual-report links download a zip holding the PDF; unzip it before reading.
  - `get_bulk_deals` (last 90 days), `get_company_overview`, `get_peer_comparison`.
- **Cache:** `data/companies/<SYM>/scr/<name>.json`, each `{fetched_at (IST), via, tool, args, warnings, partial, data}`. Names: `profit_loss`, `balance_sheet`, `cash_flow`, `ratios` (and `_standalone` versions), `quarterly`, `shareholding`, `insider`, `announcements`, `documents`, `overview`, `peers`, `credit_ratings`, `pledge_nse`, `sast`, `corporate_actions`, `shareholding_nse`, `history` (playbook base data).
- **Quirks:**
  - Figures are rounded to whole crore.
  - Consolidated statements can skip years (e.g. 2021-24 missing) while standalone has them: check the years, not just that the table is there. `mb_features.py` falls back to standalone when consolidated lacks the latest period.
  - Results announcements include newspaper copies: take the "Outcome of Board Meeting" / "Financial Result Updates" filing.
  - A call can fail mid-run (429, dropped connection): the script exits non-zero with the reason; wait and re-run before calling screener unavailable.
- **Throughput:** screener's rate limit is the bottleneck: `mb_history.py` manages about 10 companies a minute whatever the settings, and the browser gets "Too many requests" while it runs. Settled: 1 worker (2 workers drew 207 cooldowns in 7 minutes against 124); 1.2 s between requests draws no cooldowns where 1.0 s drew 24 (`SCREENER_MIN_INTERVAL=1.2`, the default in `mb_history.py`, which also widens it 0.05 s per cooldown, and in `scr_company.py`; the library's own is 0.25 s), so use it for other bulk screener scripts too. At that gap `scr_company.py` manages about 19 companies a minute with `--only overview` and about 8 with `--only statements,overview`. Logging in doesn't raise the limit, so scripts stay public and use `--login` only for screens.
