# The Google Sheet: access and layout

## Google Sheets (Google API Python client)
Scripts reach the sheet through `scripts/google_sheets.py` (the official `google-api-python-client` with `google-auth`), no model tokens; the global standard for Google APIs and credentials is `~/.common-ai/tools/google.md`.
- **Login:** `python scripts/web_get_google_token.py` (Sheets scope only) prints an authorization link; the user opens it and signs in as the sheet's owner, never the agent. The token lives in `tokens/google/token.json` (git-ignored, this project's own; never open, print or copy it) and renews itself without a browser; `--force` signs in again. A missing or unrenewable token makes every sheet script stop with "Google login needed".
- **Calls:** `sheets_call(method, body, **params)` runs one Sheets API v4 spreadsheets method on the sheet (`get`, `batchUpdate`, `values.batchGet`, `values.batchUpdate`, `values.batchClear`) and returns its JSON answer. Send values with `"valueInputOption": "RAW"` so tickers, codes and dates aren't converted the way typed input is (strings such as "TRUE", "00123", "2026-11-03 21:30" and "=1+1" stay text, numbers stay numbers, JSON `true` becomes a boolean, which checkbox-style columns and `=$Q2=TRUE` rules need); use numeric sheetIds for formatting, and read back to verify.
- Old verdicts (before 23 Oct 2026) are in the Drive copy "Stock Screener (archive, old verdicts as of 23 Oct 2026)".

## The sheet (`1yBV2fZiIR9xgZ3r-5feDKF_urqXspkPLLG9wPDoPtDU`)
Final outcomes only; the user reads it only when told all changes are in place. Light colours only, related columns merged to limit horizontal scrolling.
- **Tabs and sheetIds:** List 101, Watchlist 102, Allocation 7, Holdings 104, Rejected 108, Pending results 105 (renamed each quarter; its name is in Data!BA1), Data 106, Data Flags 10. `sheet_layout.py` owns every header and formula and pre-fills them (Data rows 2-300, List and Watchlist 2-200, Holdings/Allocation 2-100). Which columns each step writes: `/workflow/s12_listing.md` (Data, Data Flags, Pending) and `/workflow/s13_allocation.md` (Holdings, Allocation, the Data top-up columns), through `sheet_write.py` and `kite_holdings.py` (scripts write the sheet directly through `google_sheets.py`); every other column is a formula and is never written.
- **Formula columns (never written):** Data AD:AZ, BA, BD; Holdings A, E, G:L, R, S, W:Y; Allocation A, F, G, J:M, R, S, W:Y
  (`sheet_write.py` reads this line and refuses a column map that touches one; keep it on one line, tabs separated by ";". Data BA holds only the pending tab's name in BA1; Allocation P1:S4 is the checks block, with text in P and Q.)
- **Data:** one row per analysed company; written columns A:T, X:AC, BB, BC and BF:BI (S12; BG the moat verdict, BH why rejected or exited, BI what would change it) and U:V (S14). Formula columns AD:AZ and BD: live price chain, P/E now, forward P/E, PEG, the multiple and CAGR to the stock's projection year (base multiple = base EPS at that year × exit P/E ÷ live price, no dividends; CAGR over its years), the exit P/E used (held at or below the live P/E unless the analysis gives re-rating evidence), the bear multiple (exit P/E capped at 30), the buy-below price (the highest price that still clears the hurdle and the bear floor), re-rating share, the live rule reasons, the tab the row shows on, the watch type, pending flag, data-flag flag, held flag. BA1 holds the pending tab's name.
- **List:** a live formula view of Data (hidden column Z is the sorted ticker list), sorted by expected CAGR, descending: every holding, and every candidate with status List whose live price clears the price rules. When the live price breaks a rule (CAGR < 25%, bear < 0.8x, PEG > 2 or negative, forward P/E negative), or the company fails a non-negotiable or has an exit call, the row's text turns red and "Below rule (live)" lists every reason; a price rule never removes a holding.
- **Watchlist:** a live formula view of Data, by type: candidates with status List whose live price fails a price rule (waiting for the buy-below price), candidates with status Watch (waiting for dated evidence), and positions with a top-up trigger; each row shows what is awaited, the evidence so far and the next check date.
- **Rejected:** a live formula view of Data: every company the deep analysis rejected, and every exited holding once sold, newest analysis first, with why (2-3 points), what would change it, the price at analysis and now, and the analysis file. A company leaves it when a later analysis lists or watches it.
- **Allocation:** S13's actions with live price, current value, buy-below price, trim line and links to the stock's List and Watchlist rows; P1:S4 shows the largest position, the total target weight and the position count. The rule text in Q2:Q4 copies the position size and count rule of `/principles/investing_rules.md`; update it whenever that rule changes.
- **Holdings:** S13's status per holding with live price, value, P&L and links to its List and Watchlist rows.
- **Live price chain:** GOOGLEFINANCE (`NSE:SYM` or `BOM:<code>`); if N/A, screener.in's price via IMPORTXML from the "Screener URL" column (a sheet formula, not a research source); if that fails too, the stored price from the last S12.
- **Colours, one meaning each** (a cell colour overrides the row colour on that cell; red text combines with any fill): row light yellow = results pending; ticker cell light red = data flag (links to the company's first row in Data Flags); price cell light orange = screener price, light grey = stored price; Holdings Qty and Avg-cost cells light blue = Kite didn't refresh; red text = a rule broken (reasons in "Below rule (live)").
